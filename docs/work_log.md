## 2026-08-21：阶段 1 结构化方案与双智能体

- 定义严格的架构需求、Azure 资源、完整方案、审查问题和审查决策数据结构。
- 规划与审查角色使用独立 AutoGen `AssistantAgent` 上下文，仅共享本地模型客户端。
- 结构化输出采用受控 JSON 文本协议和 Pydantic 校验，拒绝多余字段与矛盾的审查决策。
- 解析器容忍外层 JSON 代码围栏和单个 JSON 对象前后的简短说明，但拒绝多对象输出，不猜测字段名或修改参数值。
- 真实 Phi-3 冒烟验证生成了 4 个 Azure 资源的可解析方案，审查智能体返回 `revision_required` 及必改项，双角色链路通过。

## 2026-08-21：阶段 2 多智能体协作闭环

- 实现初始规划、独立审查、显式 JSON 上下文传递、修订与再审的 AutoGen 调度器。
- 每个新工作阶段创建新的角色上下文，避免 Phi-3 4K 窗口同时保留重复历史；经验证的方案和审查数据由调度器显式传递。
- 终止原因区分为审查通过、达到最大轮次和运行错误，任何路径都返回结构化结果。
- 仅记录角色可见消息、解析结果、轮次和时间，不请求或展示隐藏思维链。
- 提供进程内事件回调与可选本地 JSONL trace，为 Streamlit 实时界面保留稳定边界。
- Phi-3 有时输出完整 `findings[].recommendation` 却遗漏重复的 `required_changes` 汇总；数据模型仅在该情况下原样复制已有建议，不生成新内容。
- 真实多轮运行暴露出“在原 Agent 上下文中纠正退化长输出”会挤占 4K 窗口；纠错改为新建同角色 AutoGen 上下文，只重传原任务和校验错误。
- 修订输入仅包含当前验证方案和最高三条必改建议，完整审查仍保留在 trace 中，不重复占用模型上下文。
- 对“损坏草稿 + 一个完整 JSON”输出，解析器扫描完整候选并仅在恰好一个候选通过目标 Schema 时接受；多个合法对象仍视为歧义。
- 生成参数回归 Task 1/2 已验证的贪心配置 `temperature=0.0` 与 `top_p=1.0`，降低小模型随机插入碎片。
- 对本应为字符串列表但模型输出单字符串的策略字段，仅做无损的单元素列表封装。
- 修订提示词要求保留当前资源名称与数量，在高可用字段中表达多区域策略，避免复制全部资源导致输出被截断。
- `depends_on` 的语义一致性交由审查智能体判断并向用户展示，不作为调度器的结构化终止条件。
- 真实 Phi-3 两轮运行完成“初始规划 → 审查 → 修订 → 再审”，最终以 `max_review_rounds` 可解释终止，返回最新验证方案、审查意见和 5 条可见消息。
