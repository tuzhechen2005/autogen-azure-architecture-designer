# 架构需求示例

## 示例 1：中小型电商 API

为一个中小型电商 API 设计 Azure 高可用架构。用户通过 HTTPS 访问 Web 入口，后端为 Python API，使用 PostgreSQL 保存交易数据，Blob Storage 保存商品图片。目标可用性为 99.9%，优先使用单区域多可用区，同时控制成本。只生成架构方案，不执行真实部署。

## 示例 2：企业内部文档门户

设计一个 Azure 企业内部文档门户，支持约 3000 名员工。用户通过 Microsoft Entra ID 登录，文档存储需要版本控制、软删除和备份，应用日志保留 90 天。工作时间目标可用性为 99.95%，单区域故障不应导致服务中断。只输出资源和架构建议。

## 示例 3：IoT 设备遥测平台

为 2 万台设备设计 Azure IoT 遥测平台，平均每台设备每分钟上报一条消息。需要实时告警、原始数据归档、近 30 天分析查询和运行监控。任何单一计算实例故障都不应丢失已接收消息，需要说明备份、重试和死信处理。不连接真实设备或 Azure 订阅。
